# Tasks — service-inventory-management

> Strict TDD. Every implementation task is preceded by a FAILING test task.
> Tags: `[BE]` backend · `[FE]` frontend · `[TEST]` write failing test first · `[MIGRATION]` SQL/schema file.
> ⚠️ = risk hotspot requiring extra care.
>
> **Reconciliation canonical rules applied throughout (where spec & design differ, these win):**
> - `RemoveInstalledItem` is IDEMPOTENT — already-removed item is a NO-OP returning the item (no error thrown).
> - `DELETE /contracts/:contractId/inventory/:itemId` → 200 + soft-removed item (NOT 204).
> - `ListMaterial` returns ALL rows (FE filters for dropdowns).
> - `UpdateInstalledItem type?` validated at the ROUTE (422 `INVALID_ITEM_TYPE`), not in the use-case.
> - `ConfirmInventorySuggestion` output = discriminated union `{kind:'DEVICE',item} | {kind:'MATERIAL',consumption}`.
> - Error names: `MaterialNotFoundError`, `MaterialNameConflictError`, `MaterialInUseError`, `MaterialProtectedError`, `InstalledItemNotFoundError`, `MaterialConsumptionNotFoundError`, `InvalidQuantityError`.
> - `countInUse` by **id** (FK), not name.
> - Migrations generated by agent (no user action); pushed only when user confirms deploy.

### 5.8 [BE] Crear `src/application/use-cases/RemoveInstalledItem.ts`

```ts
async execute(itemId: string): Promise<ContractInstalledItem> {
  const item = await this.inventory.getById(itemId);
  if (!item) throw new InstalledItemNotFoundError(itemId);
  if (item.status !== 'active') return item;  // idempotente — NO-OP, no error
  const removed = await this.inventory.remove(itemId);
  if (!removed) throw new InstalledItemNotFoundError(itemId);
  return removed;
}
```
